# UI Pass — June 2026 (identity-safe round)

**Status:** approved design, ready for implementation plan
**Target version:** v0.13.0
**Scope owner:** maintainer
**Companion doc:** [`UI-REDESIGN.md`](UI-REDESIGN.md) (v0.7.0 redesign), [`UI-SPEC.md`](UI-SPEC.md)

## Context

The trigger was a single feature wish: support **low-resolution renders**
for a deliberate pixel-block ("Minecraft") look. The render pixels already
exist — resolution is settable via the `width`/`height` fields (4–1024) and
`#canvas-output` already carries `image-rendering: pixelated`. The only gap
is that a low-res canvas is shown at its *native* pixel size (e.g. 64 px),
so it looks tiny. The fix is display scaling, not a new render feature.

While in there, a read-only audit of the current UI against established
best practices (WCAG 2.2 AA, modern CSS, common UX patterns) surfaced 35
verified findings. This round takes the **identity-safe** subset: real
bugs, accessibility wins, and mobile/touch fixes that do **not** change the
visual identity (no colour, type-scale, or layout-identity changes). The
look-changing items are deferred to a Round 2 that will use visual mockups.

## Goals

- Low-res renders fill the canvas frame and read as crisp pixel blocks.
- Fix five genuine correctness/robustness bugs found by the audit.
- Close the high-value, identity-safe accessibility and mobile gaps.

## Non-goals (deferred to Round 2, with mockups)

Anything that changes the visual identity: low-contrast text/border colour
bumps (audit #22/#23/#30 — real WCAG issues, but need a colour decision),
type-scale and spacing tokens (#26/#27), single-primary-action treatment
(#28), live frame-tag state (#29), presets-first IA / progressive
disclosure / divider unification / first-paint loading / persistent
main-thread indicator (#19/#20/#21/#25/#31/#32).

## Hard constraints (unchanged)

Vanilla HTML/CSS/JS, no dependencies, no build step, no ES modules,
`file://`-safe, dark/light theming preserved. See `AGENTS.md`.

## Cross-cutting decisions

1. **Canvas fit = `object-fit: contain`.** Maximal fill without distortion;
   square renders fill the frame height with matte side bars showing the
   `.canvas-frame` vignette. Fractional nearest-neighbour scaling (not
   integer) — it fills the frame maximally, matching the "fill the frame"
   intent; integer-perfect scaling was considered and rejected (leaves more
   empty matte).
2. **Drop the per-image shadow/ring.** With the canvas filling the frame,
   the existing `#canvas-output` drop-shadow + 1px ring would double the
   outer `.canvas-frame` border. Remove them; the outer frame
   (border + inner vignette) becomes the sole framing. CSS-only — no
   JS-computed card sizing.
3. **Recording cancel reuses `#btn-webm`.** During capture the button
   becomes a "Stop" toggle setting a `recordingCancel` flag; no new button.
4. **Live regions, done once.** `#status` → `role="status"
   aria-live="polite"` (assertive on error); `#progress` →
   `role="progressbar"` with `aria-valuenow`. Per-frame announcements are
   throttled to ~10 % milestones so AT is not flooded.
5. **Slider readouts follow the existing `#p-t` pattern** — a right-aligned
   mono `<output>` per range, fed by the existing `input` listener. No new
   visual idiom.

## Safety analysis (verified during the audit)

- The canvas has **no pointer interaction** (the mask is loaded from a
  file, not painted), so `object-fit` scaling cannot break any
  coordinate mapping.
- Export is unaffected: PNG (`toDataURL`) and WebM (`captureStream`) read
  the canvas **bitmap** at native resolution; CSS display scaling does not
  change exported pixels.
- The embeddable `<perlin-noise>` element is out of scope — it renders at
  display resolution (not low-res upscale) and already fills its host.

## Work items

References in parentheses are the audit finding numbers.

### Canvas fit (the original request) — `styles.css`

- **CF1** `#canvas-output`: `width:100%; height:100%; object-fit:contain;
  object-position:center`; keep `image-rendering: pixelated/crisp-edges`;
  remove the `box-shadow` (drop + 1px ring).
- **CF2** `#anim-preview` (`<video>`): `width:100%; height:100%;
  object-fit:contain`; add `image-rendering: pixelated`; match the
  shadow removal so low-res WebM playback scales up crisply too.

### Group A — genuine bugs / robustness

- **A1 — Restore the live canvas after a WebM export** (#1/#18).
  Recording adds `.ready`/`.hidden` (`perlin-studio.js:789-790`) and
  nothing removes them, so editing any param repaints a hidden canvas
  under a stale video (only reload escapes). Add a shared helper that
  removes `.hidden` from the canvas, `.ready` from `#anim-preview`, and
  re-hides/disables `#btn-webm-download`; call it from `renderOnce()` /
  `play()` / the preview-scheduling path.
- **A2 — Fix the dead Clear-mask button** (#2). `loadMaskFile` (~`:352`)
  and `clearMask` (~`:379`) toggle `els.maskClear`, which is `undefined`;
  the registered key is `els.btnMaskClear` (`:113`). The `if (els.maskClear)`
  guard means the button is never enabled. Rename both references.
- **A3 — Write clamped values back into number fields** (#15).
  `gatherParams` (`:185-247`) clamps silently and never writes back, so a
  field can read `9999` while the engine renders `1024`, and `savePreset`
  exports the **clamped** value — disagreeing with the visible field. Add
  one delegated `change` listener over the sidebar number inputs that
  re-runs the clamp and assigns `el.value`. Use `change` (not `input`) so
  it does not fight mid-typing.
- **A4 — Stop/cancel an in-progress WebM recording** (#16). Once started,
  `#btn-webm` is disabled and the loop runs every frame with no abort
  (`:742-796`); worst case (600 frames @ 1 fps) locks the UI ~10 min.
  Repurpose `#btn-webm` as a "Stop recording" toggle setting a
  `recordingCancel` flag, checked at the top of the loop; the existing
  `finally {}` already cleans up and yields a partial WebM.
- **A5 — Reject pending render promises when the worker dies** (#17).
  `worker.onerror` (`perlin-engine.js:66`) nulls the worker but never
  settles `pendingResolves`, so a crash mid-capture hangs
  `renderFrameAndWait` forever. Reject each pending promise, clear the
  array, reset `workerBusy`; the click-handler `.catch` then surfaces the
  error and restores controls.

### Group B — accessibility (identity-safe)

- **B1 — Label the Color-mode `<select>`** (#3). `label.select-row`
  (`index.html:176-184`) wraps `#p-color-mode` with no text node. Add an
  inline caption matching siblings, or `aria-label="Color mode"`.
- **B2 — Make `#status` a polite live region** (#4). `#status`
  (`index.html:356`) has no role/aria-live; all async feedback is silent
  to AT (WCAG 4.1.3). Add `role="status" aria-live="polite"`; `setStatus()`
  flips to `assertive` (or a `role="alert"` node) on error.
- **B3 — Show a live numeric value beside every range slider** (#5).
  ~16 sidebar sliders + per-stop position sliders expose no readout (only
  `#p-t` does) — an anti-pattern for a parameter-sharing tool; custom-stop
  placement is guesswork. Add a mono `<output>` per range, updated from the
  existing `input` listener (`:819-821`); add a value column in
  `renderCustomStops`.
- **B4 — Confirm PNG export in the status line** (#6). `exportPng`
  (`:669-678`) writes status only on error. Add a `setStatus("PNG saved …")`
  after `a.click()`.
- **B5 — Add `min`/`max` to number inputs that JS already clamps** (#7).
  `#p-sx/-sy/-st/-pers/-lac/-base` and the layer-2 scales/base
  (`index.html:117-138`) declare only `step`, so spinners overshoot the
  enforced range and AT announces no bounds. Set attributes to match the
  `gatherParams` clamps; add `step="1"` to the two seed fields.
- **B6 — Disable Layer-2 sub-fields when Layer 2 is off** (#8). The grid,
  blend select and mix slider (`index.html:134-150`) stay active though
  `layer2On=false` makes the engine ignore them. Add `updateLayer2Mode()`
  toggling `disabled`; call from the change handler and on init.
- **B7 — Label the dynamic custom-gradient stop inputs** (#9).
  `renderCustomStops` (`:498-520`) builds `.stop-pos`/`.stop-color` with no
  name. Set `aria-label` = `Stop N position` / `Stop N color`.
- **B8 — Expose recording progress to AT** (#24). `#progress`
  (`index.html:359`) has no `progressbar` role/values. Add
  `role="progressbar" aria-valuemin/max` and set `aria-valuenow` in
  `setProgress()`; throttle the #status announcements (B2) to ~10 %
  milestones.

### Group C — mobile / touch (identity-safe)

- **C1 — Clamp the canvas-wrap height with `dvh`** (#10). `.canvas-wrap`
  (`styles.css:774-783`) `height:calc(100vh-320px)` falls under the
  `min-height:320px` floor on short two-column landscape screens
  (721–1100 px wide, ~600–680 px tall), pushing the transport below the
  fold. Use `min-height:240px; height:clamp(240px, calc(100dvh - 320px),
  720px)` and keep the `100vh` line as a fallback.
- **C2 — Raise mobile form-input font-size to 16 px** (#11). All
  inputs/selects are 12.5 px; iOS Safari auto-zooms on focus and never
  zooms back. Inside `@media (pointer:coarse)` (or the `max-width:720px`
  block), set inputs/selects/`.num-field input` to `font-size:16px`.
- **C3 — Enlarge slider thumbs and RGB-invert checkbox rows to 24 px on
  touch** (#12). 14×14 range thumbs and the packed `grid-3` r/g/b
  checkboxes (~16–18 px tall) miss WCAG 2.5.8. Under `@media
  (pointer:coarse)`: grow the range height + thumb to 24 px
  (`margin-top:-11px`) and give `.checkbox-row label` `min-height:24px`.
  Desktop visuals unchanged.
- **C4 — Add `tabular-nums` to numeric inputs** (#13). `input[type=number]`
  (`styles.css:403-417`) uses proportional figures, so digit columns do not
  align (the transport already uses tabular figures). Add
  `font-variant-numeric:tabular-nums`.
- **C5 — Surface the WebM-ignores-mask caveat at the Export controls**
  (#14). The RGB-only/no-mask constraint is stated only in section 07
  (`index.html:267`), two sections from `#btn-webm`. When `maskApplied`,
  reveal a short `.sec-hint` near `#btn-webm`; toggle from the mask-apply
  handler and `clearMask`.

## Testing & verification

- `node --check perlin.js && node --check perlin-studio.js && node --check
  perlin-engine.js && node --check perlin-element.js && node --check
  perlin-presets.js`
- `node scripts/smoke-test.js` — math is untouched, must stay **46/46**.
- Manual browser pass (also clears the open post-refactor regression check):
  - low-res render (e.g. 48×48 and 64×64) → fills the frame, crisp blocks;
    1024² unchanged; square → matte side bars.
  - record a short WebM, download, then change a param → live canvas
    returns (A1); cancel a recording mid-way (A4).
  - clear-mask button enables/disables correctly (A2); over-type a number
    field → it snaps back to the clamp and the saved preset agrees (A3).
  - keyboard + screen-reader spot check: status announced, sliders report
    values, progress announced; mobile/touch viewport for C1–C5.
- Sandbox note: starting an HTTP server from `/Users/Shared/` may be
  blocked; if so the maintainer runs the browser pass.

## Risks

- `object-fit: contain` on `<canvas>` and `image-rendering: pixelated` on
  `<video>` are well-supported; pixelated video degrades gracefully to
  smooth where unsupported.
- The clamp write-back must use `change` (not `input`) to avoid fighting
  the user mid-typing.
- Touch-only rules are gated behind `@media (pointer:coarse)` so desktop
  pixel metrics stay exactly as designed.

audit's suggested border values did not actually reach 3:1). All ratios are
WCAG relative-luminance, against the worst applicable background.

**Text & accent — fixed to AA (≥4.5:1):**

backgrounds, focus ring and large fills keep the vibrant `--accent`.

**Borders — middle ground (decision: keep the hairline identity):**

Strict WCAG 1.4.11 (3:1) would require prominent borders that break the
minimalist look, and the focus ring is already compliant for the critical
(keyboard) path. So resting field/section borders are *lifted for visibility*
without going fully to 3:1:

| Token | dark before→after | light before→after |
|---|---|---|
| `--border` | `#22272f` 1.2:1 → `#3a414c` ~1.8:1 | `#d8d2c2` 1.4:1 → `#bdb5a0` ~1.9:1 |
| `--border-input` | `#1c2129` 1.1:1 → `#343b45` ~1.6:1 | `#cfc8b6` → `#c6bfac` |
| `--border-strong` | `#2e343d` → `#474f5c` ~2.2:1 | `#bbb4a1` → `#a89e85` ~2.5:1 |
